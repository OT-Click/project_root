В составе системы выделено несколько ключевых компонент, каждая из которых использует специализированный набор технологий для решения своих задач. Фронтенд реализован как SPA и Telegram Mini App на базе React с типобезопасной маршрутизацией и управлением состоянием через TanStack-библиотеки и стилизуется с помощью SCSS и CSS Grid. Бэкенд-микросервисы написаны на Python 3.12 с использованием FastAPI, FastStream для event-driven взаимодействия и RabbitMQ с quorum-очередями и sharding-плагином. Для NLP-парсинга задействованы spaCy, Google ADK и PaidenticAI, а матчингу резюме служат алгоритмы TF-IDF/BM25 на базе scikit-learn. Обмен данными внутри системы идёт через RabbitMQ, а внешние интеграции — Bot API, SMTP, Stripe/YooMoney и MinIO S3 с boto3. Наконец, наблюдаемость обеспечивается OpenTelemetry, хранением метрик в Prometheus и визуализацией в Grafana.

## 1. Frontend

### 1.1 SPA на React  
- **React** как основа для построения одностраничного приложения (SPA) обеспечивает компонентный подход и высокую отзывчивость интерфейса.  
- **TanStack Router** предоставляет 100% типобезопасную маршрутизацию с поддержкой data fetching и stale-while-revalidate кэша.  
- **TanStack Store** используется для локального управления состоянием через сигналы, упрощая подписку на изменения и оптимизацию рендеринга.  
- **SCSS** (Sass синтаксис `.scss`) даёт расширенные возможности препроцессинга: вложенность, миксины, переменные и т.д.  
- **CSS Grid** применяется для гибкой двухмерной раскладки, упрощая создание адаптивных интерфейсов канбан-доски.

### 1.2 Telegram Mini App  
- Реализован тоже на **React SPA**, повторяя логику веб-приложения с WebSocket-соединениями для real-time обновлений.  
- Использует тот же стек маршрутизации и стейт-менеджмента (TanStack Router/Store) и SCSS + CSS Grid для стилизации.

## 2. Bot Service (S1)  
- **Python 3.12** как платформа разработки, включая новые возможности f-строк, предложения “Did you mean…” и улучшенные типы.  
- **FastAPI** для высокопроизводительного HTTP API с валидацией типов и автогенерацией OpenAPI схем.  
- **aiogram** для работы с Telegram Bot API и обработки вебхуков.  
- **RabbitMQ** с **quorum-очередями** и **sharding-плагином** обеспечивает надёжную репликацию и разделение нагрузки.  
- Внешние точки входа защищены через **Kong Gateway** (JWT, rate-limit) и **Keycloak** (OIDC).

## 3. Ingest Service (S2)  
- **Python 3.12** и **FastStream** для асинхронной обработки событий из очереди `vacancy.raw`.  
- **spaCy** для промышленного NLP-парсинга текста вакансий с извлечением ключевых полей.  
- **Agent Development Kit (ADK)** от Google для гибкого подключения кастомных агентов парсинга.  
- **PaidenticAI** (в составе пайплайна) для дополнительных AI-фич (требует уточнения документации).

## 4. Matcher Service (S3)  
- **Python 3.12**, **FastAPI** и **scikit-learn**: TF-IDF через `TfidfVectorizer` и BM25-алгоритм для оценки релевантности резюме.  
- Логика выбора одного CV с `score ≥ 0.55`.

## 5. Sender Service (S4)  
- **Python 3.12**, **FastAPI** и **HTTPX** для синхронных/асинхронных HTTP-запросов к Bot API.  
- Отправка через `sendMessage` и `sendDocument`.  
- **SMTP**-фоллбек: если `telegram_chat_id` отсутствует, формируется и отправляется email-отклик.

## 6. Billing Gateway (S5)  
- **Python 3.12**, **FastAPI** и библиотека **stripe-python** для интеграции с Stripe.  
- Обработка вебхуков Telegram Wallet, YooMoney и Stripe, нормализация событий и публикация в `subscription.events`.

## 7. Subscription Core (S6)  
- **Python 3.12**, **FastAPI** и **SQLModel** для работы с PostgreSQL через ORM.  
- БД организована в кластере Patroni + pgBouncer (pattern Database-per-Service).

## 8. File Uploader (S7)  
- **Python 3.12**, **FastAPI** и **boto3** для взаимодействия с MinIO S3 (S3-совместимое хранилище).  
- Генерация публичных URL и публикация события `file.uploaded`.

## 9. Observability & Telemetry  
- Сбор метрик и трейсинг через **OpenTelemetry**; хранение метрик в **Prometheus**.  
- Визуализация в **Grafana**; структурированные логи могут храниться в Loki/ElasticSearch.  
- Трассировка запросов и зависимостей реализована в **Jaeger**.

Такой стек обеспечивает гибкость, масштабируемость и надёжность каждого из компонентов, а единые подходы к логированию и мониторингу упрощают оперативное сопровождение системы.
