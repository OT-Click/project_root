## Feature: [[NF01] Настройка инфраструктуры и рабочих окружений](https://github.com/OT-Click/project_root/issues/72)

_**_As a_** DevOps-инженер, **_I want to_** настроить все необходимые рабочие окружения, CI/CD и инфраструктуру, **_So that_** я мог обеспечить стабильный процесс разработки и эксплуатации._

### Scenario: [[NS01.01] Создание локального окружения для разработки](https://github.com/OT-Click/project_root/issues/69)

- **_When_** я настраиваю окружение для локальной разработки
- **_Then_** должен быть доступен Docker Compose со всеми необходимыми сервисами:
  | Сервис     | Конфигурация                       |
  | :--------- | :--------------------------------- |
  | RabbitMQ   | Quorum-очереди + Sharding Plugin   |
  | MongoDB    | Шардированный кластер              |
  | PostgreSQL | Patroni + pgBouncer                |
  | MinIO      | Erasure Coding 6:2                 |
- **_And_** разработчики могут запустить окружение одной командой
- **_And_** все сервисы могут взаимодействовать друг с другом в изолированной сети

### Scenario: [[NS01.02] Настройка CI/CD для автоматических сборок](https://github.com/OT-Click/project_root/issues/70)

- **_When_** я настраиваю GitHub Actions для CI/CD
- **_Then_** для каждого микросервиса должен быть настроен pipeline:
  | Этап              | Действие                             |
  | :---------------- | :----------------------------------- |
  | Lint/Test         | Запуск Ruff/Pyright/Тесты            |
  | Build             | Docker Buildx с multi-arch           |
  | Artifact Registry | Push образов с тегами commit/branch  |
- **_And_** pipeline запускается автоматически при push в рабочие ветки
- **_And_** пропускается при наличии `[skip ci]` в сообщении коммита
- **_And_** результаты сборки отображаются на badge в `README.md`

### Scenario: [[NS01.03] Управление конфигурациями в Kubernetes](https://github.com/OT-Click/project_root/issues/71)

- **_When_** я создаю конфигурацию оркестрации для Kubernetes
- **_Then_** для каждого сервиса должны быть созданы манифесты:
  | Ресурс        | Назначение                          |
  | :------------ | :---------------------------------- |
  | Deployment    | Определение replicas и стратегии    |
  | Service       | Внутренняя коммуникация и LB        |
  | ConfigMap     | Настройки без перезапуска подов     |
  | Secret        | Хранение чувствительных данных      |
- **_And_** должен быть настроен Helm Chart для установки всего проекта
- **_And_** значения переменных окружения должны храниться отдельно в `values.yaml`
