## Feature: [[NF03] Мониторинг и наблюдаемость](https://github.com/OT-Click/project_root/issues/79)

_**_As a_** оператор системы, **_I want to_** настроить комплексный мониторинг и сбор метрик, **_So that_** я мог оперативно выявлять и устранять проблемы в системе._

### Scenario: [[NS03.01] Настройка сбора и хранения метрик](https://github.com/OT-Click/project_root/issues/76)

- **_When_** я настраиваю инструменты мониторинга
- **_Then_** должен быть развернут стек:
  | Компонент      | Назначение                         |
  | :------------- | :--------------------------------- |
  | Prometheus     | Сбор и хранение временных рядов    |
  | OpenTelemetry  | Инструментация и трейсинг          |
  | Grafana        | Визуализация и алертинг            |
  | Loki           | Сбор и индексация логов            |
  | Jaeger         | Визуализация распределённых трейсов |
- **_And_** метрики должны храниться не менее 30 дней
- **_And_** все микросервисы должны быть настроены для отправки метрик

### Scenario: [[NS03.02] Создание дашбордов для мониторинга](https://github.com/OT-Click/project_root/issues/77)

- **_When_** я создаю дашборды в Grafana
- **_Then_** должны быть доступны следующие визуализации:
  | Дашборд              | Содержимое                           |
  | :------------------- | :----------------------------------- |
  | System Overview      | CPU, память, диск, сеть по нодам      |
  | Service Health       | Доступность и latency сервисов        |
  | RabbitMQ Queues      | Размеры очередей, throughput, ошибки  |
  | Database Performance | QPS, latency, connections, hit ratio  |
  | Business Metrics     | Обработанные вакансии, конверсии      |
- **_And_** должны быть настроены алерты для критических показателей
- **_And_** алерты должны отправляться в Slack и по email

### Scenario: [[NS03.03] Настройка структурированного логирования](https://github.com/OT-Click/project_root/issues/78)

- **_When_** я настраиваю систему логирования
- **_Then_** все сервисы должны отправлять логи в JSON-формате
- **_And_** логи должны содержать контекст:
  | Поле         | Содержимое                       |
  | :----------- | :------------------------------- |
  | service      | Имя микросервиса                 |
  | trace_id     | ID распределённого трейса        |
  | request_id   | Уникальный ID запроса            |
  | user_id      | ID пользователя (если есть)      |
  | environment  | dev/stage/prod окружение         |
- **_And_** должен быть настроен ротация логов и удаление старых данных
