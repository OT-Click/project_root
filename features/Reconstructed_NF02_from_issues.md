## Feature: [[NF02] Обеспечение надёжности и отказоустойчивости](https://github.com/OT-Click/project_root/issues/75)

_**_As a_** системный администратор, **_I want to_** настроить механизмы высокой доступности и резервного копирования, **_So that_** я мог гарантировать бесперебойную работу системы._

### Scenario: [[NS02.01] Настройка кластера высокой доступности](https://github.com/OT-Click/project_root/issues/73)

- **_When_** я настраиваю отказоустойчивое окружение для production
- **_Then_** должны быть развернуты кластеры:
  | Компонент  | Конфигурация                          |
  | :--------- | :------------------------------------ |
  | RabbitMQ   | Quorum-кластер из 3 нод               |
  | MongoDB    | Шардированный кластер, shard-key user_id |
  | PostgreSQL | Patroni × 3 ноды + pgBouncer          |
  | MinIO      | 4 ноды с Erasure Coding 6:2          |
- **_And_** система должна выдерживать отказ одного узла без потери данных
- **_And_** время восстановления при отказе не должно превышать 10 секунд

### Scenario: [[NS02.02] Настройка системы резервного копирования](https://github.com/OT-Click/project_root/issues/74)

- **_Given_** я настраиваю систему бэкапов для PostgreSQL
- **_When_** я создаю расписание резервного копирования
- **_Then_** должны выполняться следующие операции:
  | Инструмент | Расписание                       | Тип бэкапа          |
  | :--------- | :------------------------------- | :------------------ |
  | wal-g      | Каждые 6 часов                  | Full + инкременты   |
  | wal-g      | В реальном времени               | WAL-архивация       |
  | pgBackRest | Еженедельно                     | Full backup         |
  | pgBackRest | Ежедневно                       | Дифференциальный    |
- **_And_** все резервные копии должны храниться в MinIO S3
- **_And_** должен выполняться автоматический тест восстановления каждую пятницу
